# Модели и конфигурации

Базовый детектор геометрический. Результат дополнительных моделей следует оценивать отдельно: наличие подключённых весов не доказывает прирост полноты.

| Режим | Конфигурация | Поведение |
|---|---|---|
| Базовый | `gabarit.yaml` или профиль Falcon | геометрия; лес Sakhalin Ai по умолчанию выдаёт диагностический score |
| Помощь исходного леса | `component_assist.yaml` | положительная помощь после геометрических и временных ограничений |
| Собственный лес | `component_trained.yaml` | JSON-веса проекта, поддержка подтверждения от трёх наблюдений |
| Собственный лес с двумя наблюдениями | `component_trained_fast.yaml` | более раннее подтверждение подходящего тела при поддержке модели |
| Нейросетевая дальняя ось | `learned_pandar.yaml`, `learned_falcon_ros.yaml` | FarBevNet и отдельная дополнительная ветка детекции |

Профили `component_*.yaml` используют Pandar-настройки по умолчанию. Для Falcon загрузите правильный профиль датчика и явно объедините с ним раздел `models`; нельзя заменить им конфигурацию осей.

## Sakhalin Ai

Перенесён исходный компактный лес из 17 деревьев и C++-эталон из `ikonushok/lidar-metro-obstacle-detection`, commit `3cfd31843b911f278c08f49e53a09b1a5efa1d92`. Признаки: число точек, три размера, объём, плотность, дальность центра и ближайшей точки. Вычисление соответствует float32-контракту исходника; сравнение с оригинальным C++ проверяется тестом. Лицензия MIT сохранена в `gabarit/vendor/sakhalin_ai/LICENSE`.

## Собственный лес

`gabarit/models/component_forest_v1.json` содержит 31 дерево, максимальная глубина 7, seed 20261110. Исполнение — NumPy, обучение — scikit-learn 1.9.1 из `requirements-training.txt`. Данные признаков получены вставкой синтетических объектов в облака; положительные возвраты определяются по реально изменённым индексам после трассировки и перекрытия.

| Разделение | Запись-фон | Строки | Положительные | Recall при выбранном пороге |
|---|---|---:|---:|---:|
| train | `doubleT_platform` | 4313 | 1082 | 0,7292 |
| calibration | `roundT_squareT_pressureGate_squareT` | 2748 | 495 | 0,6727 |
| test | `roundT_pressureGate_roundT` | 2225 | 454 | 0,6410 |

Порог 0,9901312175192601 выбран на calibration с нулём ложноположительных компонент в этом наборе. Эти показатели относятся к синтетическим компонентам; они не равны полноте всего детектора или реальных препятствий. В дополнительной временной проверке 24 сцен два наблюдения вместо трёх дали 137 → 131 пропущенный кадр до подтверждения и шесть более ранних подтверждений, но политика выбрана после просмотра этого набора. Нужен новый слепой тест.

Воспроизведение обучения из поставляемых признаков в отдельной среде:

```sh
python -m pip install -r requirements-training.txt
python scripts/train_component_forest.py --features training/component_forest_v1.features.json.gz --out results/training-reproduced
```

Сравните SHA-256 `results/training-reproduced/component_forest.json` и поставляемых весов. На проверенной среде совпадение получено. Полный сбор признаков из bag требует `--data`, `--reference` и исходных записей. Не смешивайте разделения по соседним кадрам одного проезда.

## FarBevNet

Перенесены сеть дальней оси, остаточный блок и BEV-геометрия Attention Please из `BelousovArts/fod`, commit `baebf57a4169697aa61d017fcea8e2374ef135a0`. Подготовка входа адаптирована к координатам текущего пути. Веса скачиваются `scripts/fetch_path_models.py` с проверкой закреплённой идентичности в `.models/attention_please/far_bev.pt`.

Сеть включается `models.learned_path`, устройство задаёт `models.device`, интервал inference — `path_interval` (по умолчанию 10 кадров). Проверяются неопределённость, допустимая поправка и последовательное согласие. Геометрическая ветка сохраняет собственные prior и подтверждение. При отсутствии PyTorch или checkpoint причина отключения видна в `models.far_path`.

Подтверждена работоспособность CUDA на локальной RTX 5070 Ti, однако полный режим ROS/RViz/web с CUDA не аттестован на 10 Гц. В сохранённом Windows-прогоне 201 кадра p95 времени ядра составил 222,96 мс. Это не сопоставимый замер с короткими CPU ROS-участками: отличаются среда, состав обработки и границы времени.
