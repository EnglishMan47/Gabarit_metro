# Данные и оценка качества

Оценка разделяет регрессию на фиксированной синтетике, поддержку объектов исходными маркерами и независимую разметку реальных вторжений в маршрут. Эти источники отвечают на разные вопросы и не объединяются в одну «точность».

## Наборы и назначение

| Набор | Объём полного прогона | Что известно |
|---|---:|---|
| Шесть исходных проездов | 2488 кадров | записи-фоны и положительный проезд; полного независимого GT нет |
| Falcon `falcon_test_second_dark` | 4443 | полный replay; 582 тревожных кадра не объявляются автоматически истинными или ложными |
| `new_data` | 11271 | полный replay с исправлением вертикального хвоста; 0 тревог не доказывает отсутствие пропусков |
| Синтетическая запись организаторов | 1510 | сопоставление с добавленными возвратами, отдельный протокол |
| Три записи с MarkerArray | 1667 | независимая геометрия маркеров и поддержка точками |
| Фиксированная регрессия | 118 сцен, 112 положительных | два фоновых проезда, заданные формы, seed, лучевые вставки |
| Временная проверка модели | 24 сцены, 22 положительные | использовалась для выбора политики подтверждения; development, не слепой тест |

Массовый датасет на 20 000 кадров из плана С1 ещё не выпущен. Перечисленные 118 сцен не являются 118 независимыми реальными маршрутами.

## Основная регрессия

```sh
python scripts/regression_suite.py --data data/extracted/for_hackathon --out results/regression --workers 2 --check
```

Манифест, сжатые reference-профили и SHA-256 находятся в `tests/fixtures/regression118`. Сначала сравнивается идентичность геометрии входов, затем качество каждой сцены. `--check` обнаруживает потерю прежней цели, рост пропусков после подтверждения или сторонних тревог относительно baseline. Он не проверяет автоматически все возможные метрики и не заменяет независимую приёмку.

Удержание после первого подтверждения и обнаружение за весь проезд — разные показатели. Сохраняйте также eligible missed frames до подтверждения, расстояние первого кандидата, первого подтверждения и задержку. Нельзя называть 112/112 объектов «100% recall» для всех реальных условий.

## Полный replay

```sh
python scripts/evaluate.py data/extracted/falcon_test --config config/falcon_prime_ros.yaml --out results/falcon --save-path --progress 200
python scripts/evaluate.py data/extracted/finalist_20261018/new_data --config config/gabarit.yaml --out results/new-data --save-path --progress 200
```

`summary.json` хранит события, распределения времён и межкадровую согласованность. `frames/*.jsonl` — решения. `--save-path` добавляет оценённую геометрию. Межкадровая RMSE после компенсации движения не равна ошибке относительно измеренных рельсов. `--step > 1` меняет доступную историю подтверждения и не эквивалентен полному прогону.

## Независимая ручная разметка

```sh
python scripts/annotation_review.py --data data/extracted/falcon_test --config config/falcon_prime_ros.yaml --out results/review-falcon --every 200
```

Откройте `review.html`, оцените сырые облака без боксов детектора, явно отметьте «есть», «нет» или «неизвестно» и сохраните `annotations.json`. Начальные значения UNKNOWN не являются отрицательными метками. Установите, известен ли маршрут и достаточно ли виден объект; сомнительные кадры сохраняйте неизвестными.

```sh
python scripts/evaluate.py data/extracted/falcon_test --config config/falcon_prime_ros.yaml --annotations results/review-falcon/annotations.json --out results/falcon-labelled
```

Измеряются только известные метки обработанных кадров. Редкая выборочная разметка не покрывает все события, боксы и видимость объекта. Для публикации нужны независимый протокол, второй проверяющий, согласование спорных кадров и отдельный закрытый набор после фиксации параметров.

## Маркеры

```sh
python scripts/evaluate_markers.py --data data/extracted/finalist_markers_20261019 --out results/markers
```

Сопоставление использует timestamp, frame_id и принадлежность реальных возвратов геометрии MarkerArray, без оси детектора как эталона. Метрика показывает поддержку видимых размеченных объектов. Сам по себе активный маркер не означает вторжение в выбранный маршрут; несопоставленный трек может быть реальным немаркированным объектом. Поэтому это не общие binary FP/FN.

## Производительность

Отделяйте `timing_ms.total` ядра, `read_decode` чтения SQLite/CDR, `end_to_end` оценщика, callback ROS и фактические частоты входных timestamp и выходных сообщений. Дополнительно считайте p50/p95/p99, долю превышений 100 мс, пропущенные и повторные source timestamp, прогрев и условия графики.

В запущенном workspace-контейнере:

```sh
docker compose exec gabarit python scripts/benchmark_ros.py /data/extracted/for_hackathon/doubleT_obstacle --frames 130 --warmup 20 --header-frames 201 --out /output/ros-benchmark.json --require-10hz
```

Скрипт сам управляет воспроизведением и подключает web-пробу; RViz должен быть запущен. Для больших записей добавьте `--no-cache` и достаточно большой `--header-frames`. Сохраняйте образ, SHA исходников, CPU/GPU, версии, лимиты контейнера, источник данных и загрузку машины. Перед длительным запуском проверьте `--help` и место на диске.

Воспроизводимость обучения — в [MODELS.md](MODELS.md). Сравнение с победителями на одном оборудовании и GT, AP/IoU на OSDaR23, ложные тревоги на 10 км и Jetson Orin остаются будущими экспериментами.
