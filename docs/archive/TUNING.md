# Настройка детектора

## Разрешённые параметры

Настройке подлежат только общие геометрические и статистические пороги: ширина коридора, параметры пола и рельсов, диапазонные размеры вокселей, минимальное число точек, доля совпадения с нормальной сценой и длина временного подтверждения. Имена bag, номера кадров и координаты конкретных объектов в правила детекции не входят.

## Воспроизводимый поиск

```powershell
python scripts/tune_detector.py --step 10
```

Скрипт проверяет фиксированную сетку `background_reject_fraction = 0.45, 0.50, 0.55`. Сначала максимизируется полнота двух положительных целей на прореженной инженерной выборке, затем минимизируется доля сырых тревог на пяти штатных записях. Результат сохраняется в `artifacts/evaluation/tuning.json`.

В выполненном прогоне значения 0,45 и 0,50 дали одинаковую полноту 36/36 и 86 тревожных кадров из 231 штатного; 0,55 сохранило полноту, но увеличило число тревожных кадров до 92. Выбрано 0,50 как середина равного устойчивого диапазона, чтобы не размещать финальный порог на границе.

Подтверждение события проверялось отдельно по длительности ложных интервалов полного baseline. Три последовательных совпадения удаляют двухкадровые всплески и дают задержку два кадра. Гистерезис в три кадра объединяет краткие провалы одного трека. Эти значения одинаковы для всех bag.

Итоговая проверка выполняется заново на всех кадрах с `--step 1`. Поэтому числа из tuning-отчёта не выдаются за финальные метрики качества.
