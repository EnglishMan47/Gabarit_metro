# Рассмотренные готовые решения и подходы

Перед разработкой и по ходу работы мы разобрали открытые проекты по обработке лидарных облаков — прежде всего китайских команд и компаний (Baidu Apollo, OpenMMLab / Shanghai AI Lab, PaddlePaddle, Livox/DJI, HKU MARS, HESAI), а также европейские, корейские и японские проекты и публикации о контроле железнодорожного габарита. Цель — понять, что можно взять готовым, а что нужно делать самим.

**Вывод:** готового решения, которое работает с Pandar128 в тоннеле метро, ищет *неизвестные* препятствия без размеченных данных, читает bag-файлы без ROS и укладывается в 100 мс на CPU, не нашлось. Нейросетевые детекторы обучены на автомобильных датасетах (KITTI, nuScenes, Waymo) и распознают заданные классы — машины, пешеходов, велосипедистов; для тоннеля с единственным проездом с препятствием их не обучить и не проверить. Поэтому решение построено на геометрии среды метро, а из рассмотренных проектов взяты идеи.

## Что сделано иначе, чем в найденных решениях

- **Путь дальше видимости рельсов.** Рельсы различимы до 40–60 м; дальше путь продолжается слежением фильтрами Калмана за стенами, полом и сводом тоннеля. В рассмотренных работах о железной дороге коридор строится только по видимым рельсам.
- **Самокалибровка по рельсам** вместо заданной внешней калибровки: в данных два разных крепления лидара.
- **«Нормальный тоннель» через свойства среды**, а не через запомненную карту конкретного перегона: вытянутость вдоль пути, продолжение за габарит, непрерывность «пол–свод», повторяемость кронштейнов. Благодаря этому решение не привязано к конкретным записям.
- **Скорость без IMU и одометрии** — по корреляции текстуры тоннеля.
- **Испытания трассировкой лучей**: синтетические объекты вписываются в реальные облака с затенением. Похожие приёмы используют для аугментации обучающих данных в автомобильных задачах; мы применяем их для проверки дальности обнаружения и в интерфейсе оператора.
