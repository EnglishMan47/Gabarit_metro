# Формат результата

## Топики ROS 2

| Топик | Тип | Содержание |
|---|---|---|
| `/gabarit/obstacle` | `std_msgs/Bool` | `true` — впереди подтверждённое алгоритмом препятствие |
| `/gabarit/distance` | `std_msgs/Float32` | расстояние до ближайшего препятствия, м (`NaN`, если путь свободен) |
| `/gabarit/free_distance` | `std_msgs/Float32` | путь проверен и свободен до этого расстояния, м |
| `/gabarit/status` | `std_msgs/String` | полный JSON-результат кадра (ниже) |
| `/gabarit/markers` | `visualization_msgs/MarkerArray` | габарит, ось пути, рамки и подписи препятствий для RViz2 |
| `/gabarit/obstacle_points` | `sensor_msgs/PointCloud2` | точки подтверждённых препятствий |
| `/gabarit/view_cloud` | `sensor_msgs/PointCloud2` | рабочее облако для RViz в нормализованном `gabarit_view` |
| `/gabarit/view_markers` | `visualization_msgs/MarkerArray` | габарит и препятствия в том же `gabarit_view` |

`markers` и `obstacle_points` сохраняют систему входного облака (`header.frame_id`).
Выходы `view_*` используют REP-103: x вперёд, y влево, z вверх,
ноль высоты на головках рельсов. Это позволяет RViz показывать разные лидары
с одинаковыми настройками. `/gabarit/reset` (`std_srvs/Trigger`) сбрасывает
историю при переключении bag и перечитывает конфигурацию, выбранную менеджером.

В `view_cloud` фон прореживается для графики (бюджет 30 тысяч точек), а точки
кандидатов и препятствий сохраняются все. Вход алгоритма не прореживается этим
ограничением просмотра. Облако публикуется напрямую как стандартный CDR
PointCloud2; получателю не требуется специальный тип сообщения.

## JSON кадра (`/gabarit/status`, веб-интерфейс, `scripts/evaluate.py`)

```json
{
  "frame": 57,
  "stamp": 1788354628.81,
  "status": "OBSTACLE",              // CLEAR | CHECK | OBSTACLE | DEGRADED
  "obstacle": true,
  "nearest_distance_m": 55.6,        // евклидово расстояние от лидара до ближайшей точки объекта
  "nearest_track_distance_m": 55.5,  // вдоль пути
  "free_distance_m": 55.5,           // до препятствия или до конца проверенного пути
  "observed_until_m": 107.0,         // свежий горизонт измерений
  "current_observed_until_m": 107.0, // свежие измерения текущего кадра
  "envelope_until_m": 107.0,         // визуальный горизонт с удержанием
  "analysis_range_m": 200.0,        // предел анализа профиля; Falcon — 350 м
  "envelope_held": false,
  "envelope_coasted_frames": 0,
  "speed_kmh": 0.0,                  // скорость поезда по лидару
  "time_to_obstacle_s": null,
  "turnout_ahead_m": null,           // распознанная впереди стрелка (маршрут на ней не определён)
  "obstacles": [{
    "track_id": 3, "confirmed": true,
    "distance_m": 55.6, "s_m": 55.5, "lateral_m": 0.35,
    "box": {"s": [55.5, 55.9], "d": [0.1, 0.6], "h": [0.18, 1.55]},  // вдоль пути / поперёк / над головкой рельса
    "size_m": [0.4, 0.5, 1.37],
    "points": 112, "rings": 12,
    "low": false,                    // true — низкий объект на рельсе
    "single_beam": false,            // широкое низкое тело на одном луче при доказанной стоянке
    "height_reference": "path",      // path или local_rail — база высоты box.h
    "transparent": false,            // true — прозрачный объект (двойной отклик лазера расщеплён)
    "confidence": 0.98,
    "first_seen_m": 55.7,            // на каком расстоянии объект впервые стал кандидатом
    "confirmed_at_m": 55.6,
    "reasons": ["112 точек на 12 лучах"]
  }],
  "pending": [],                     // кандидаты, ещё не подтверждённые (статус CHECK)
  "candidates": [ ... ],             // все кластеры кадра с причиной отбраковки ("rejected")
  "calibration": {"height_m": 1.48, "pitch_deg": -0.9, "roll_deg": -3.5, "valid": true},
  "points": {"filtered": 12, "filter_examined": 550},
  "state_reset": null,              // time_rewind | duplicate_stamp | time_gap | frame_id_change
  "path_guard": {"active": false, "isolated_near_returns": 0},
  "realtime": {"target_hz": 10, "budget_ms": 100, "deadline_met": true},
  "timing_ms": {"decode": 20.1, "track": 30.2, "egomotion": 2.4, "filter": 1.1, "detect": 14.9, "tracking": 0.1, "total": 67.7}
}
```

`scripts/evaluate.py` сохраняет записи построчно (`frames/<bag>.jsonl`) и сводку
(`summary.json`: кадры с тревогой, события, задержки p50/p95). Поле `path_guard`
показывает включение проверки рельсов при устойчивом рассеянном шуме; в сводке
сохраняются число измеренных кадров и число включений. Флаг `--save-path`
добавляет в JSONL геометрию `track` (`s`, `c`, `z`, неопределённость и рельсы)
для проверки габарита. Без флага большой профиль в каждую строку не записывается.

Удержание габарита по умолчанию ограничено четырьмя кадрами. Свободная
дальность ограничена свежими измерениями: прогноз не продлевает проверенный
свободный путь. `filter` входит во время `detect`; складывать эти два поля
нельзя. `total` измеряет всю обработку, а чтение SQLite и CDR отдельно
учитывает оценщик в `read_decode` / `end_to_end`.

ROS-узел также добавляет `ros_timing_ms`: `input_decode`, `pipeline`,
`outputs`, `web_pack`, `total`. Поле `latency_ms` содержит время callback до
подготовки статуса. Построение `view_*` выполняет ограниченная фоновая очередь,
а `web_pack` включает передачу результата в live-цепочку и не измеряет полную
доставку или отрисовку. Исходные `markers` и `obstacle_points` при наличии
подписчиков могут строиться в callback. Доставка DDS и ожидание в middleware
не входят в callback: частоту `/gabarit/status` и совпадение входных timestamp
нужно измерять отдельно. `timing_ms.total` относится только к ядру.

## Диагностика моделей

`models.components` содержит режим леса, число оценённых и поддержанных
компонент и сведения об исполнении. `component_policy: score` выдаёт оценки,
не изменяя принятие геометрического кандидата. `assist` разрешает ограниченную
помощь по правилам профиля. `models.far_path` показывает состояние FarBevNet,
причину отключения или ошибки, факт inference на текущем кадре, результаты
проверки поправки и число дополнительных кандидатов/подтверждений. Поля
диагностики зависят от состояния ветки; отсутствие inference на одном кадре
не означает, что сеть не загружена: учитывается `path_interval`.

В тексте выше показан пример JSON с поясняющими комментариями и сокращениями;
он не является готовым валидным JSON-файлом. Реальные JSONL не содержат
комментариев или многоточий. `confidence` и оценки моделей не объявляются
калиброванной вероятностью безопасности. Подробности: [MODELS.md](MODELS.md).

## Автоматический результат

Детекция и временное подтверждение работают без ответа машиниста. Остановка и скорость просмотра задаются пользователем. Расчёта тормозного пути и команд управления движением нет. Ручные метки прежних версий доступны в админ-панели как архив только для чтения и экспорта.
