# Руководство пользователя

## Что делает система

«Габарит» получает облака точек 3D-лидара, установленного в кабине поезда, и для каждого кадра (10 раз в секунду) отвечает:

- **путь свободен** — и на каком расстоянии путь проверен;
- **впереди препятствие** — расстояние до него, положение относительно оси пути, высота, размер, уверенность, с какого расстояния объект замечен впервые.

Препятствие — всё, что находится внутри **габарита движения** (по умолчанию 2,2 м шириной и 3,0 м высотой над головкой рельса вдоль реальной оси пути, включая кривые), и не является конструкцией тоннеля. Система не пытается узнать «человек это или ящик»: она знает, где проходит путь и как выглядит нормальный тоннель, и сообщает обо всём, что в эту картину не вписывается. Дополнительно выдаются скорость поезда (восстанавливается по лидару), тормозной путь, время до препятствия, расстояние до стрелочного перевода.

## Режимы работы

| Режим | Команда | Когда использовать |
|---|---|---|
| Веб-интерфейс | `python -m gabarit web --data <каталог>` | просмотр и проверка записей, демонстрация, испытания |
| Консоль по кадрам | `python -m gabarit run <bag>` | быстрый ответ «есть/нет, расстояние» по записи; `--jsonl` — полный результат |
| Пакетная оценка | `python -m gabarit evaluate <каталог> --out <каталог>` | прогнать все записи и получить сводку тревог и задержек |
| Оценка дальности | `python -m gabarit synthetic <каталог> --out <каталог>` | на каком расстоянии находятся объекты разного размера |
| ROS 2 узел | `./ros2/run_ros2.sh` или Docker | работа в составе ROS 2 (`ros2 bag play`, реальный лидар), RViz2 |

## Установка

1. Python 3.10 или новее.
2. Windows: `powershell -ExecutionPolicy Bypass -File install.ps1`. Linux/macOS: `./install.sh`.
3. Проверка: `python -m gabarit check --data <каталог с записями>` — покажет версии, найденные записи, число кадров и топики.

Записи — стандартные ROS 2 bag (каталог с `metadata.yaml` и `*.db3`). Каталог сканируется рекурсивно; имя топика и система координат определяются автоматически. Если лидар смотрит вдоль другой оси, чем в предоставленных данных, укажите `sensor.forward_axis` в конфигурации (`-y` для набора, `+x` по соглашению ROS).

## Работа в веб-интерфейсе

1. Запустите `start_web.cmd <каталог>` (Windows) или `./start_web.sh <каталог>` и откройте http://localhost:8000.
2. Выберите запись в верхнем списке, нажмите ▶ (пробел). ← → — кадр назад/вперёд, скорость — ×0,25…×5.
3. Слева — 3D-сцена: серое облако — тоннель, оранжевые точки — попавшие в габарит, красные — подтверждённое препятствие. Зелёный объём — габарит; серый — участок, где путь не подтверждён измерениями. Камеры: кабина, сзади, сверху, сбоку, «к цели», свободная (клавиши 1–6).
4. Справа — статус крупно, скорость, свободный путь, тормозной путь, время до препятствия, задержка обработки, карточки объектов.
5. Внизу 3D-сцены — схема пути 0–200 м: где объект и хватает ли тормозного пути.
6. При новом препятствии появляется запрос **«Подтвердить / Ложная тревога / Позже»**. Решения попадают во вкладку «Журнал» и выгружаются в CSV.
7. «Анализ всего проезда» прогоняет запись целиком и отмечает события на таймлайне; щелчок по событию — переход к нему.
8. Вкладка «Испытание» — поставить на путь виртуальный объект (человек, ребёнок, ящик, предмет на рельсе, тележка, кабель) на нужном расстоянии или Shift+щелчком по коридору. Объект вписывается в облако трассировкой лучей и неподвижен относительно пути — видно, с какого расстояния его найдёт система.
9. «Параметры» — ширина и высота габарита, нижняя граница, горизонт, режим чувствительности (строгий / сбалансированный / чувствительный). Здесь же результат самокалибровки лидара.

## Результаты для машинной обработки

`python -m gabarit run <bag> --jsonl result.jsonl` и `python -m gabarit evaluate` пишут JSON на каждый кадр; в ROS 2 то же публикуется в `/gabarit/status`, а главное — в `/gabarit/obstacle` (Bool) и `/gabarit/distance` (Float32, NaN если свободно). Поля описаны в [RESULT_FORMAT.md](RESULT_FORMAT.md).

## Настройка

Файл [`config/gabarit.yaml`](../config/gabarit.yaml); достаточно указать только изменённые ключи, например:

```yaml
envelope: {width: 2.1, height: 3.0}
tracking: {confirm_hits: 4, confirm_window: 5}   # строже: меньше ложных, задержка больше
```

Передать: `python -m gabarit web --config my.yaml`, `python -m gabarit run <bag> --config my.yaml`, `./ros2/run_ros2.sh config:=my.yaml`. Смысл параметров — [ALGORITHM.md, раздел 11](ALGORITHM.md#11-параметры-влияющие-на-результат).

## Производительность

Один кадр — 40–75 мс на одном ядре CPU (GPU не нужен). При `ros2 bag play` в реальном темпе кадры не пропускаются. Если узел не успевает (слабая машина), он берёт самый свежий кадр, а не копит очередь — задержка не растёт.

## Типичные вопросы

| Ситуация | Что делать |
|---|---|
| «нет записей» в интерфейсе | проверьте путь `--data`: в нём должны быть каталоги с `*.db3`; `python -m gabarit check --data …` |
| Порт 8000 занят | `python -m gabarit web --port 8010` |
| Статус «НЕТ ОПОРЫ ПУТИ» | рельсы и стены не распознаны: лидар не смотрит вдоль пути или неверно задана `sensor.forward_axis` |
| ROS 2 узел не получает кадры | используйте CycloneDDS (`ros-humble-rmw-cyclonedds-cpp`, `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`) в узле и в `ros2 bag play` |
| Тревога за стрелкой | маршрут на стрелке по облаку не определить; интерфейс показывает расстояние до стрелки, решение — за оператором |

## Ограничения

См. [ALGORITHM.md, раздел 12](ALGORITHM.md#12-ограничения) и [EXPERIMENTS.md](EXPERIMENTS.md): неопределённость пути вдали на стрелках и расширениях тоннеля, малые предметы ниже 0,15 м над головкой рельса видны только вблизи, стекло и чёрные поглощающие поверхности дают мало отражений.
